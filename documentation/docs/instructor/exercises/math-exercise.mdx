# Math Exercise

## Overview

Math exercises train **equational reasoning**: a student transforms a starting expression into a goal, or proves an equation, by applying rewrite rules step by step in an interactive block editor. Artemis grades most submissions automatically and only escalates to a tutor when automatic grading is inconclusive.

A math exercise consists of one or more **problems**. Each problem defines:

- a **goal mode** — *Transformation* (rewrite a start expression into a target), *Equation* (prove both sides equal), or *Induction* (prove a statement by induction over a variable);
- the **expressions** — a source and target (transformation), a goal equation (equation), or a goal statement and an induction variable (induction);
- one or more **graders** — the in-process **Path checker**, and/or the remote Regate backends (see [Grading and Review](#grading-and-review));
- the **rules** the student may apply, drawn from the shared block registry.

Conducting a math exercise follows the same three steps as other exercise types:

1. Setup of the exercise in Artemis
2. Participation by a student
3. Assessment by tutors — only when a submission needs manual review

## Setup

Open **Course Management**, navigate into **Exercises** of your course, and create a new math exercise.

<Image src={createExercise} alt="Create a math exercise" size={ImageSize.large} caption="Creating a new math exercise" />

Fill out the general exercise settings (title, points, dates) and configure each problem in the authoring form.

<Image src={authoringForm} alt="Math exercise authoring form" size={ImageSize.large} caption="The math exercise authoring form" />

For each problem you set the goal mode, the graders, the expressions, and the allowed rules. The per-problem block editor lets you build the expressions from the same blocks the student uses.

<Image src={problemEditor} alt="Per-problem block editor" size={ImageSize.large} caption="Configuring a problem in the block editor" />

Pick one or more grading backends in the **Graders** multi-select. Only backends that support the chosen goal mode are selectable — the rest are greyed out (for example, the induction-only provers cannot grade a transformation problem). The graders run in the listed order and the first conclusive verdict wins (see [Grading and Review](#grading-and-review)).

<Image src={graderSelection} alt="Grader multi-select" size={ImageSize.large} caption="Selecting grading backends; graders that don't support the goal mode are disabled" />

To get started quickly, use **Start from a template** to pre-fill a problem from a curated set of basic equational-reasoning examples (left/right identity, commutativity, associativity, a fraction identity, and an induction proof). You can edit everything afterwards.

<Image src={starterTemplates} alt="Starter templates" size={ImageSize.large} caption="Pre-filling a problem from a curated starter template" />

Created math exercises appear in the exercise list. Opening one shows its detail view with statistics and the list of submissions; submissions awaiting manual review are flagged here as well.

<Image src={exerciseDetail} alt="Math exercise detail" size={ImageSize.large} caption="Math exercise detail view with statistics" />

## Participation

Students work in an interactive block editor. Starting from the problem's start expression, they select a rule from the palette and apply it to a node, building a derivation toward the goal.

<Image src={studentEditor} alt="Student math editor" size={ImageSize.large} caption="The student block editor" />

Students can request **hints** — Artemis suggests applicable rules and previews the resulting expression.

<Image src={studentHints} alt="Hints" size={ImageSize.large} caption="Suggested next rules (hints)" />

When the derivation reaches the goal, the editor confirms it.

<Image src={studentGoalReached} alt="Goal reached" size={ImageSize.large} caption="The derivation reaches the goal" />

On submit, the submission is graded (see [Grading and Review](#grading-and-review)). For in-process grading the score appears immediately.

<Image src={studentGraded} alt="Graded submission" size={ImageSize.large} caption="A graded submission" />

## Grading and Review

Math exercises are graded automatically by the backends you selected for the problem:

- **Path checker** (in-process) — validates the derivation step by step against the rule library on the server and grades synchronously.
- **Remote Regate backends** (eggregate, leanregate, coqregate, cvc5regate) — equational-reasoning provers reached over HTTP. These grade asynchronously, and the result is pushed to the student over a websocket when it lands.

When several graders are configured, they run in the listed order and the **first conclusive verdict wins**; a grader that abstains or is unavailable falls through to the next. Backends differ in reasoning strength, so the verdicts are weighed by a **capability tier**: a full pass from any backend is trusted, but a *rejection* from a weaker backend never overrides a stronger backend that could not decide — that case is routed to review instead.

Because the Path checker cannot reason beyond its fixed rule library, listing it *after* a stronger backend makes it a fallback: only its full passes count, and any rejection or partial result goes to manual review. The authoring form warns you when this is the case.

<Image src={graderFallbackWarning} alt="Path-checker fallback warning" size={ImageSize.large} caption="The authoring warning shown when the Path checker sits behind a stronger backend" />

Which backends are available depends on the goal mode — the induction-only provers (coqregate, cvc5regate) appear only for induction problems.

<Image src={graderInduction} alt="Grader options for induction" size={ImageSize.large} caption="For induction problems the formal provers become selectable and the transformation-only backends are disabled" />

Optionally, a slower formal **certifier** can double-check the fast preliminary verdict from the grader above.

<Image src={graderCertifier} alt="Optional certifier" size={ImageSize.large} caption="An optional certifier that confirms the preliminary verdict" />

When automatic grading is **inconclusive** (an undecided prover verdict) or **fails** (a backend is unavailable), the submission is never scored zero — it is escalated to **manual tutor review**, and the student sees an "awaiting tutor review" state.

<Image src={studentUnderReview} alt="Awaiting tutor review" size={ImageSize.large} caption="A submission escalated to manual review" />

## Assessment

Submissions awaiting review appear in the standard **assessment dashboard**. A tutor starts a new assessment, which locks the next submission so that no two tutors grade the same one.

<Image src={assessmentDashboard} alt="Assessment dashboard" size={ImageSize.large} caption="The assessment dashboard with the review queue" />

In the assessment view the tutor sees the student's full derivation, the automatic verdict, and any configured sample solution, and assigns a manual score with optional feedback. The assessment can be saved as a draft or submitted as final.

<Image src={assessmentView} alt="Math assessment view" size={ImageSize.large} caption="Assessing a locked submission" />

### Complaints

If a student complains about an assessment, a tutor or instructor — other than the original assessor — reviews the complaint in the assessment view and accepts or rejects it, adjusting the score if warranted.
